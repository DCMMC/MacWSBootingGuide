MacWS fullscreen DisplayStream ownership handoff evidence
Target: iPad13,6, iPadOS 16.3.1, macOS 13.4 chroot
Date: 2026-08-03

Reproducer:
  misc/macws_display_handoff_probe.m

The probe opens two independent XPC clients. Client one subscribes to the
physical fullscreen desktop; client two subscribes 750 ms later. Every frame
lease is released. No WindowServer, display daemon, or UI process is stopped
by the probe.

Rejected implementation (stop old graph, create a new graph):

  PROBE_RC=0 WS_BEFORE=75537 WS_AFTER=78356
  MACWS-DISPLAY workspace-handoff old-stream=1 new-client=0x14e71c2e0 reason=single-desktop-capture-owner
  MACWS-DISPLAY workspace-start id=13 display=2388x1668 scale=2.000 transport=window-iosurface-composite
  MACWS-DISPLAY layer-start failed base=0 layer=10 error=-308

The changed PID is the failure witness. Merely serializing ownership while
recreating SkyLight streams was not stable.

Production implementation (move the live capture graph and retained latest
IOSurfaces to the new client):

  PACKAGE_PROBE_BEFORE
  78356 /System/Library/PrivateFrameworks/SkyLight.framework/Resources/WindowServer
  79399 /usr/local/bin/macwsdisplayd

  PACKAGE_PROBE_AFTER
  78356 /System/Library/PrivateFrameworks/SkyLight.framework/Resources/WindowServer
  79399 /usr/local/bin/macwsdisplayd
  MACWS-DISPLAY workspace-start id=1 display=2388x1668 scale=2.000 transport=window-iosurface-composite
  MACWS-DISPLAY workspace-handoff stream=1 layers=11 new-client=0x131f111a0 transport=live-graph-transfer
  first event=stopped message=全屏工作区已转移到当前前台窗口

There is no second workspace-start, no second layer-start set, and no
layer-start failure during the handoff. The same WindowServer and
macwsdisplayd PIDs survive.
