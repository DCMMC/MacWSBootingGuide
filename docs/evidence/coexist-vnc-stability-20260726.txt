Coexistence VNC / Terminal stability evidence — 2026-07-26
==========================================================

Device: iPad13,6, iOS 16.3.1 (20D67)
Guest: macOS 13.4 chroot
Mode: MACWS_AGX_NATIVE=1, coexistence, real iOS AGX driver

This record distinguishes three independent defects. It does not promote
process uptime to rendering evidence: the final witnesses are on-wire RFB
pixels, stable hashes, the mmap header, and advancing completion logs.

1. Pre-fix watchdog stop (runtime-confirmed)
------------------------------------------------

The user's ordinary one-click invocation did start WindowServer, OSXvnc, and
Terminal. It then disappeared because the safety watchdog recorded:

    [macos_gui] watchdog: SAFETY TRIP: WindowServer 高 CPU 样本累计达到 30 秒（阈值 70%，当前 98%），已自动停止以防过热

WindowServer logged about one immediate synthetic completion per display
iteration, including:

    #### COEXIST API SwapCancel #3600 ...
    #### IOMFB CANCEL-COMPLETION schedule #3600 ...
    #### IOMFB CANCEL-COMPLETION delivered #3600 ...

The completion is now delayed synchronously by one 16,667-us interval at the
SwapEnd ownership boundary. This preserves exactly one real SwapCancel and one
matching completion; it does not force a success branch or raise the thermal
threshold. The post-change sample was:

    root 32105  55.7 ... WindowServer -virtualonly -daemon

The watchdog remained armed at its original CPU policy:

    WS CPU>=70% for 30s

--------------------------------------------------

display and then overwrote it with a Terminal intermediate:

    #### VNC-BLIT candidate #0 ... 2388x1668 pf=80
    #### VNC-MMAP /tmp/macws_vnc_fb 2388x1668 sz=15932752
    #### VNC-BLIT captured 2388x1668 pf=80 -> mmap (detiled)
    #### VNC-BLIT candidate #2 ... 1140x798 pf=80
    #### VNC-MMAP /tmp/macws_vnc_fb 1140x798 sz=3638896
    #### VNC-BLIT captured 1140x798 pf=80 -> mmap (detiled)

The actual pre-fix file header then read:

    magic=1447969606 width=1140 height=798 stride=4560

This is why a 1194x834 RFB desktop showed full-display content, a magnified
Terminal subtexture, or black between updates. StartComposite owns both display
and intermediate composites; a size threshold of 1000x600 was not a display
identity.

The corrected publisher keeps the largest accepted PF80/PF115 composite area
for the WindowServer lifetime and rejects smaller intermediates. Post-fix log:

    #### VNC-MMAP /tmp/macws_vnc_fb 2388x1668 sz=15932752

    #### VNC-BLIT reject intermediate #2 1140x798 area=909720 displayArea=3983184

The file remained:

---------------------------------

    sudo bash /var/jb/usr/macOS/bin/macos_gui.sh start coexist --experimental

It starts WindowServer, persistent OSXvnc, and Terminal, and explicitly owns
