MacWSHost M3 control-plane evidence -- 2026-07-26
================================================

Scope
-----

This record covers version 0.3 of the iPadOS-native control center, its root
typed-XPC service, package-first initialization, cold userspace-restart path,
touch bridge, and an App-launched native-AGX GlassDemo capture. It does not
claim that every macOS window is already an independent UIKit scene, nor that
the two explicitly labelled compatibility sentinels are protocol fixes.

Target: iPad13,6, iOS 16.3.1, Apple M1 GPU. No OSXvnc-server was running.

1. Control boundary and root service
------------------------------------

MacWSHost connects to the Mach service `com.macwsguide.host.control`.
`macwshostd` runs as uid 0 and accepts only the operation constants in
`include/macws_control_protocol.h`; application launch resolves one of four
compiled `AllowedApp` records. There is no arbitrary shell/path field in the
wire protocol.

Verbatim daemon startup:

    macwshostd starting pid=63531 protocol=1 uid=0
    published com.macwsguide.host.control

2. First-install failures and upstream fixes
--------------------------------------------

The first cross-built package supplied a fat libmachook whose two slices still
reported `platform IOS`. A real chroot probe exited 133. Its bash crash report
showed EXC_BREAKPOINT/SIGTRAP at:

    _check_internal_content.cold.1
    _check_internal_content
    os_variant_has_internal_diagnostics
    libSystem_initializer

After changing LC_BUILD_VERSION to platform 1 / macOS 13.0, the probe advanced
and dyld reported the next independent problem verbatim:

    warning could not apply interposing tuples in /usr/local/lib/libmachook.dylib
    symbol not found in flat namespace '_macws_install_quartzcore_frame_info_hook'

Source inspection showed the function body inside `#ifdef FORCE_M1_DRIVER`
while its call was generated for the non-native build. The call is now guarded
by the same condition. Native builds still compile and execute it; this is a
linkage-invariant correction, not a skipped initializer.

Package postinst now patches both Mach-O slices, extracts thin arm64e and arm64
files, signs twice, and trusts the final CDHashes. A fresh dpkg run proved that
this occurs before the developer build helper:

    [slice-0:0x100000c/0x0] LC_BUILD_VERSION platform=2 ... -> macOS 13.0
    [slice-1:0x100000c/0x80000002] LC_BUILD_VERSION platform=2 ... -> macOS 13.0
    patched /var/jb/usr/macOS/lib/libmachook.dylib
    Split libmachook into thin arm64e + arm64 injection libraries.
    MacWS Host installed. Open the app to initialize, repair, start, and control macOS.
    ==> Package postinst already installed thin slices; keeping them.

------------------------------

Immediately after `launchctl reboot userspace`, hostd came back without a
manual load:

    RECONNECTED

Before opening the app, neither WindowServer nor the input job was present.

    1785003265.244 control-status connected=YES busy=YES rootfs=YES ws=NO input=NO frame=NO phase=检查并修复启动环境… error=
    1785003268.413 control-status connected=YES busy=NO rootfs=YES ws=YES input=YES frame=YES phase=就绪 error=

The matching launch jobs were:

    63852  0  com.apple.WindowServer
    63834  0  com.macwsguide.input
    63531  0  com.macwsguide.hostd

The watchdog logged its corrected cold-start policy:

    [macos_gui] watchdog: armed (load>=60 after 90s grace or >=12 WS restarts / 45s -> auto-stop)

Earlier in the session a userspace restart inherited a one-minute load of
110, and the old watchdog stopped a healthy new WindowServer after seven
seconds despite zero WS restarts. The 90-second load grace fixes that stale
metric while retaining restart-count protection throughout the grace period.

A full hardware reboot was not performed. Dopamine must first reactivate the
rootless `/var/jb` bootstrap; an app installed inside that bootstrap cannot run
before it exists. Once active, the App owns the initialization/repair/start
path and no SSH step is required.

6. Current architectural boundary
---------------------------------

M3 is a native iPadOS control and presentation shell around one full-display
frame. Multiple-scene capability is declared, but the tested SpringBoard still
rejects the second scene request. Per-CGSWindow identity, lifecycle, crop,
IOSurface/fence transport, keyboard, scroll, right-click policy, and an
interactive soak remain future milestones. Process uptime alone is not used as
the success criterion here; the witnesses are XPC completion, live launchd
state, observed input coordinates, completed Metal status, independent control
pixels, and visible nonzero output.
