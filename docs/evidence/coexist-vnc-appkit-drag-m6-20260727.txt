MacWS coexist VNC input M6: restore AppKit pressed-button invariant
=================================================================

Date: 2026-07-27
Device: iPad13,6, iOS 16.3, macOS 13.4 chroot
Mode: `macos_gui.sh start coexist --experimental --no-terminal`
Display: native AGX diagnostic path, RFB 2388x1668

Scope and patch discipline
--------------------------

This milestone does not set an NSControl value, call its action directly, or
replace a validation result with a constant. It restores process-local input
state that a hardware CGEvent normally establishes before AppKit receives a
mouse-down. Outside a synchronous synthetic RFB gesture, the bridge returns the
original AppKit pressed-button result unchanged.

----------------------------------------------------------------

Only the pressed-button path reaches the real tracker setup:

    +784   objc_alloc_init (_NSMouseTracker at runtime)

Therefore the previous synthetic NSEvent pair was incomplete: it delivered a
valid mouseDown object to the right control, but `+[NSEvent
pressedMouseButtons]` still returned zero because no permitted CGEvent had
updated global mouse state. AppKit consequently called startTracking and then
stopTracking without entering `_NSMouseTracker`.

Implemented invariant bridge
----------------------------

`AppInputBridge.m` installs a scoped interposition on the NSEvent class method
`pressedMouseButtons`. It calls the original implementation and ORs left-button
bit 0 only while `sendEvent(mouseDown)` synchronously owns the synthetic RFB
gesture. The corresponding up remains an ordinary NSEvent consumed by AppKit's
own tracker.

The buffered fallback now keeps only the latest move. RE above shows
`_NSMouseTracker` explicitly enables event coalescing; runtime LLDB measured
one `continueTracking:` call for a four-move prefilled burst, and the selected
point was an intermediate sample. A one-move sequence reliably lands at the
release coordinate, so retaining historical positions is actively harmful in
this fallback.

Safety and remaining work
-------------------------

Every diagnostic run ended with `misc/cleanup_all.sh`; final state contained no
WindowServer, OSXvnc-server, GlassDemo, or debugger process.

This milestone fixes stationary clicks and correct drag release semantics. The
current fallback still waits for mouse-up before dispatching a drag, so it is
not yet live interactive tracking. The next milestone is to use AppKit's
documented subthread `postEvent:atStart:` path to feed move/up events while the
main thread is inside `_NSMouseTracker`, with ordered backpressure and a
release-safe fallback.
