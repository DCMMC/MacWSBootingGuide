Private Metal event selector translation — 2026-07-29
=====================================================

Scope
-----

This closes the private `-[MTLDevice newEvent]` constructor failure seen in
Chromium 148/ANGLE. It is a cross-version IOGPU selector translation backed by
the actual macOS 13.4 binary and iOS 16.3 runtime code. It does not force a
kernel return value, replace an event object, or bypass event completion.

---------------------------------

  eventInitCode +0x070: e7 53 00 91 81 02 80 52 02 00 80 d2 03 00 80 52
  eventInitCode +0x080: 04 00 80 d2 05 00 80 d2 6a da 0e 95 80 00 00 34

Adapter and chroot regression (runtime-confirmed)

macOS-to-iOS IOGPU translation table. A fresh standalone chroot process exited

did not fire:

The exact VS Code build under test was Code 1.130.0 / Electron 42.6.0 /
Chromium 148.0.7778.280. Its post-fix log recorded eight sampled successful
0x18->0x14 calls, zero failed translated calls, and zero
`MACWS-NEW-EVENT #N` fallback invocations.

A 512x512 WebGL2 fill control with explicit timer queries disabled completed

`EXT_disjoint_timer_query_webgl2`, which previously caused the CDP run to stop
completing, now produced:

This is a bounded correctness/stability witness, not a long soak. It also
separates the remaining bottleneck: GPU queries complete in about 0.38 ms,
while observed rAF intervals remain tens of milliseconds. The next target is
the Chromium/WindowServer presentation and in-flight scheduling path, not the
private event constructor or raw fragment workload.
