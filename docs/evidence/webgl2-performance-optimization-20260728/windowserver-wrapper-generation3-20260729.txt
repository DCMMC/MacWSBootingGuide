WindowServer leading-wrapper and VS Code generation-3 evidence (2026-07-29)
============================================================================

Scope
-----

This milestone separates two command-list framing issues found during a clean
VS Code/WebGL2 regression:

1. Chromium's trailing wrapper advanced from generation 2 to generation 3.
2. WindowServer retained a macOS type-9 leading wrapper after its nested
   subtype-1 record had been normalized for the iOS 16.3 AGX kernel.

No completion, Metal error, or validation result is overridden here.  Both
changes validate and translate captured producer records before the real iOS
IOGPU submission.

  SHA-256 bf14ff937dcf789af0b23bb59376540f818fbdab9a27ef7b8a5d11f0ad354d1f

iOS-native control and translation
----------------------------------

The project LLDB attached to the early-held iOS-native MacWSHost PF550
read-surface control.  Its real selector-0x1a submission completed with status
4 and nil Metal error.  LLDB saved:

- native KCMD: 0x820 bytes,
  SHA-256 b0e11e0d0177749a8114ca1bb20550eaa6c858d33101208eb0de1f1303304ea1
- native segment list: 0x130 bytes,
  SHA-256 ffb991a1c94f9b4ee26613a213290a22a4364f1a8ce332f7d1b680c8233ba3f9
- direct subtype-1 span 0x820; record end 0x7f8; 23 resources
- direct segment list; no type-9 or list wrapper

The failing WindowServer record has the same normalized record end 0x7f8.
The translator now removes its 0x10 KCMD wrapper, wrapper-specific 0x18 record
suffix, and matching 0x18 list wrapper, updates the record/range to
0..0x820, and submits the resulting direct 0x820/0x130 iOS layout.

Thermal and lock-screen conclusion
----------------------------------

The erroring WindowServer was independently measured at roughly 75-88% of one
CPU while repeating ProtectionViolation observations, so that loop is a
runtime-confirmed heat source.  It is not valid to reverse the attribution and
claim heat caused those protocol errors: the direct-layout A/B removed the
errors without changing the device or workload.

Locking can still change iOS visible-frame scheduling and is retained as a
long-soak confounder.  It cannot explain the entire rAF gap: the earlier
controlled run was unlocked and Thermal pressure Nominal yet still measured a
49.3-ms iPad rAF median versus 16.7 ms on M1.  A same-process locked/unlocked
A/B remains required before assigning a numeric lock-screen penalty.

Test isolation
--------------

An invocation audit caught an unrelated deferred SSH workflow replacing the
measured WindowServer during an earlier cold test.  `macos_gui.sh` now supports
an opt-in token file at `/var/jb/var/mobile/macws_test_lease`; while present,
mutating start/restart/stop operations must provide the same
`MACWS_TEST_LEASE_TOKEN`.  Status remains read-only and unblocked.  The lease
is absent during ordinary use and was removed after every bounded test.
