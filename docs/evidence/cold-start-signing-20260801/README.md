# Direct-package arm64e cold-start guard — 2026-08-01

## Failure witness

`bash-2026-08-01-041316.ips` is the complete device crash report generated by
the arm64e chroot smoke test after a direct on-device `make package` omitted
`LIBMACHOOK_ON_DEVICE_BUILD=1`.

Runtime-confirmed fields from that report:

```text
exception: EXC_BREAKPOINT / SIGTRAP
esr: (Breakpoint) pointer authentication trap DA
x0: OBJC_CLASS_$_MTLFakeDevice
frame 0: readClass(objc_class*, bool, bool) + 112
stack: readClass -> map_images_nolock -> _objc_init -> libSystem_initializer
```

This is the same load-time invariant documented in `libmachook/Makefile`: the
on-device lld arm64e output requires chained fixups. It is not an AMFI page
failure and not an application-level crash.

## Root fix and package witness

`libmachook/Makefile` now sets `LIBMACHOOK_ON_DEVICE_BUILD := 1` when the target
rootless Theos `common.mk` exists under `/var/jb/var/mobile/theos`, unless the
caller explicitly supplied the variable. The macOS cross-build has no such
path and remains unchanged.

The regression was then tested through the exact previously failing interface:

```text
$ make -C libmachook -pn | grep '^LIBMACHOOK_ON_DEVICE_BUILD'
LIBMACHOOK_ON_DEVICE_BUILD := 1

$ dpkg-deb -x com.kdt.macosbooter_0.3.4_iphoneos-arm64.deb <temporary-dir>
$ otool -l <temporary-dir>/var/jb/usr/macOS/lib/libmachook.dylib | grep -c LC_DYLD_CHAINED_FIXUPS
1

$ sudo dpkg -i com.kdt.macosbooter_0.3.4_iphoneos-arm64.deb
$ sudo bash /var/jb/usr/macOS/bin/run_bash.sh -c 'echo packaged-chroot-smoke-ok'
packaged-chroot-smoke-ok
```

WindowServer remained stopped throughout this package validation.
