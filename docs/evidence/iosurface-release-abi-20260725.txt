# IOSurface release ABI root-cause and native GlassDemo stability — 2026-07-25

## Result

The post-frame IOSurface growth was not a QuartzCore container leak and was not
an AGX resource-destroy failure.  It was an IOSurface user-client ABI mismatch:
the macOS 13.4 framework releases a client with two `IOConnectTrap1` calls,
while iOS 16.3.1 releases the same client with one selector-1 scalar method.
The iOS kernel did not retire objects when it received the macOS traps.

`libmachook` now translates only the two exact calls in the verified macOS
IOSurface image.  A Metal-free probe, high-churn WindowServer, and a normal
GlassDemo/VNC run all runtime-confirm the fix.

## Adapter invariants

`IOConnectTrap1_new` changes behavior only if all of these match:

1. the caller image basename is `IOSurface`;
2. its loaded Mach-O UUID is the exact macOS UUID above;
3. the return offset and preceding BL word match one of the two exact sites;
4. the trap index is 4 or 5 as appropriate;
5. at the second site, thread-local state contains the same `(connect,
   surfaceID)` recorded at the first site.

At the first site it records the pair and returns success because iOS has no
corresponding first operation.  At the second site, after macOS has released
client+0x60, it issues the real iOS selector-1 scalar call and returns the real
kernel status.  All mismatches fall through to the original `IOConnectTrap1`.
This is a narrowly versioned protocol translation, not a global trap bypass.

## Remaining boundary

This closes the catastrophic IOSurface lifetime/Jetsam blocker.  It does not
promote the existing temporary KCMD subtype-1/subtype-3 byte-deletion scaffold
to a production ABI fix, and the cancel-completion shim is still opt-in through
`/tmp/macws_cancel_completion`.  Those are separate protocol milestones.
